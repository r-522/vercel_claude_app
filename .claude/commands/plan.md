実装計画を作成する。$ARGUMENTS に要件・機能概要を指定する。

## 手順

1. **要件の理解**
   $ARGUMENTS を分析し、不明点があれば実装前に確認する。
   既存の CLAUDE.md と context/architecture.md を読み、プロジェクトの制約を把握する。

2. **アーキテクチャスキルの適用**
   以下の観点でアーキテクチャを検討する：
   - Next.js App Router のデータフロー（Server Component vs Client Component）
   - API ルートの責務分離（認証・ロジック・レスポンス）
   - 状態管理（`useChat`、フック、Ref）

3. **影響ファイルの特定**
   変更・新規作成が必要なファイルを列挙する：
   ```
   変更: src/...（変更理由）
   新規: src/...（ファイルの役割）
   ```

4. **タスクの分解**
   実装を依存順に並べた順序付きタスクリストに分解する：
   1. ...
   2. ...（1 の完了を前提）
   3. ...

5. **リスクの特定**
   以下のカテゴリでリスクを評価する：
   - **認証リスク:** Middleware (`src/proxy.ts`) の保護範囲を変更するか？新しい API ルートに認証は必要か？
   - **シークレットリスク:** 新しい環境変数が必要か？クライアントコードに漏れる可能性はないか？
   - **破壊的変更リスク:** `MODELS` / `EFFORT_LEVELS` の変更は既存の会話に影響するか？
   - **パフォーマンスリスク:** transport パターンや安定参照の制約に違反していないか？
   - **Vercel 固有リスク:** in-memory state はインスタンス間で共有されない（rate limiter など）

6. **構造化計画の出力**
   templates/design-doc.md を読み、そのテンプレートに従って計画書を出力する。
   計画書には以下を含める：
   - 背景・目的
   - 影響ファイル一覧
   - 実装タスク（順序付き）
   - リスクと対策
   - 完了基準（型チェック・lint パス、動作確認項目）
