ドキュメントを更新する。$ARGUMENTS に変更内容・更新対象を指定する。

## 手順

1. **変更内容の特定**
   $ARGUMENTS から何が変わったかを把握する。以下のカテゴリに分類する：
   - アーキテクチャ変更（新コンポーネント、新フック、新 API ルート）
   - パターン変更（コーディング規約の追加・変更）
   - 設計判断（なぜその実装を選んだかの記録）
   - 環境変数の追加・変更

2. **context/patterns.md の更新**
   新しいコーディングパターンを導入した場合、または既存パターンを変更・廃止した場合に更新する。
   以下の形式で記録する：
   - パターン名
   - 適用対象（どのファイル・コンポーネントか）
   - 実装方法
   - 理由（なぜこのパターンか）

3. **context/decisions.md の更新**
   非自明な設計判断（他の選択肢を検討した上での決定、トレードオフを受け入れた決定）を記録する。
   以下の形式で記録する：
   - 決定日
   - 決定内容
   - 理由
   - 却下した代替案

4. **CLAUDE.md の更新**
   以下のいずれかに該当する場合は CLAUDE.md を更新する：
   - 新しいコンポーネント・フック・ライブラリを追加した
   - ディレクトリ構造が変わった
   - モデル (`MODELS`) または努力レベル (`EFFORT_LEVELS`) を変更した
   - 重要なコーディング規約を追加・変更した

5. **.env.local.example の更新**
   新しい環境変数を追加した場合は `.env.local.example` を更新する。
   **禁止事項:** 実際の値を `.env.local.example` に書かない。プレースホルダー（例: `COOKIE_SECRET=your-32-plus-char-secret-here`）のみ記載する。

6. **変更報告**
   更新したファイル一覧（絶対パス）と、各ファイルの変更内容を報告する。
